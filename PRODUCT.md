# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Visitors exploring zeffree's work as a memorable professional portfolio.

## Product Purpose

Let the actual projects lead an immersive, experimental portfolio. Visitors
should understand a project, explore its preview, and launch it without having
to learn an unfamiliar navigation system.

## Operating Context

The public homepage at https://zeffree.github.io/ links to independently deployed
GitHub Pages applications, explicitly selected external sites, and their source
repositories when available.

## Capabilities and Constraints

- Discover public, non-fork repositories with GitHub Pages enabled.
- Honor explicit exclusions and additional projects, including Azure-hosted apps.
- Never invent a source repository or activity date for an external site.
- Private source links may be explicitly listed, but private repository metadata
  is not automatically included in the public catalog.
- Preserve working project and source links and the existing `projects.json`
  array contract.
- Use real preview images and project details, not live embedded applications.
- Retain useful static HTML when JavaScript or optional browser features are
  unavailable.
- Frameworks and 3D engines are permitted if justified, but native HTML/CSS/JS
  suit the selected project-screen experience.
- Do not modify the linked applications as part of this homepage.

## Brand Commitments

- Keep the zeffree identity and factual project information.
- The selected concept is a Project Control Room: an immersive wall of project
  screens with direct keyboard, touch, and index navigation.
- The work itself is the evidence. Do not invent testimonials, usage statistics,
  business outcomes, or live telemetry.

## Evidence on Hand

Project facts come from GitHub repository metadata, the presentation overrides
in `portfolio.config.json`, and the linked public applications. Preview images
are snapshots, not a promise that the depicted data remains current.

## Product Principles

- Make actual work more memorable, not harder to reach.
- Discover new projects while honoring the owner's explicit inclusions and exclusions.
- Keep expressive exploration optional and direct navigation visible.
- Explain missing content and failed actions rather than masking them.

## Accessibility & Inclusion

Target WCAG 2.2 AA, keyboard access, visible focus, generous touch targets, and
OS-aware reduced motion. No information may depend on hover, dragging, depth,
color alone, or animation.
